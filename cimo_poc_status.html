DAY 04 · 2026-04-15~16
Flink Job 3개 + E2E 파이프라인 검증
✅ 완료
  • ✅
    SendRequestJob — 검증·채널분배·DB INSERT
    ValidationOperator(txId·채널·receiver·messageBody) → ChannelDispatchOperator → RateLimitOperator(채널별 TPS) → dispatch 토픽 5개 분배 + msg_send_history INSERT
  • ✅
    SendResultJob — 결과분류·DB UPDATE·Metrics 집계
    ResultCodeClassifier(STORE/RETRY/FALLBACK/DLQ) → PostgreSQL UPDATE(status·result_code·dispatched_at·delivered_at) → MongoDB UPDATE → 1분 Tumbling Window → msg_send_metrics INSERT
  • ✅
    RetryJob — 지수백오프 재처리 + DLQ 분류
    keyBy(txId) → RetryProcessFunction(ValueState 재시도횟수) → 타이머(30s/60s/120s) → dispatch 재발송 or topic.send.dlq
  • ✅
    Maven 빌드 — fat-jar 25MB (am-flink-fat.jar)
  • ✅
    metrics_helper.py — Prometheus Counter 중복 등록 방지
    get_or_create_counter() / get_or_create_histogram() · REGISTRY 체크 후 재사용
  • ✅
    E2E 검증 — DISPATCHING → DELIVERED 확인
    txId: 00000000000010310600100000000000003 · SMS · DELIVERED · 10000
  • #1
    SendResultJob RESTARTING
    원인: PostgreSQL 비밀번호 하드코딩 불일치
    → .env 환경변수 주입 구조로 변경
  • #2
    SendRequestJob RESTARTING
    원인: setKafkaProducerConfig JMX Producer ID 충돌
    → Properties props 및 setKafkaProducerConfig 제거
  • #3
    RetryJob RESTARTING (1차)
    원인: 동일 JMX 충돌
    → 동일하게 제거
  • #4
    RetryJob RESTARTING (2차)
    원인: RetryEvent Serializable 미구현 → Checkpoint 직렬화 실패
    → implements java.io.Serializable + serialVersionUID 추가
  • #5
    RetryJob RESTARTING (3차)
    원인: TaskManager 슬롯 2개로 Job 3개 실행 불가
    → numberOfTaskSlots: 2→6 증가
  • #6
    Mock Adapter 전체 기동 실패
    원인: Prometheus Counter 모듈 레벨 전역 선언 → uvicorn 재시작 시 중복
    → metrics_helper.py 작성 + sys.path.insert 순서 수정
  • #7
    DB INSERT 없음
    원인: SendRequestJob에 buildPostgresSink() 미구현
    → JdbcSink INSERT 메서드 추가
  • #8
    SendResultJob Checkpoint 실패
    원인: Instant.parse()가 +09:00 오프셋 미지원
    → ZonedDateTime.parse().toInstant() 변경
  • #9
    INSERT SQL 오류 — ON CONFLICT
    원인: tx_id 컬럼에 UNIQUE 제약 없음
    → ON CONFLICT 구문 제거
  • #10
    INSERT SQL 오류 — success_rate 컬럼 없음
    원인: 실제 msg_send_metrics 테이블과 SQL 불일치
    → 실제 컬럼(total/success/fail_count) 기준으로 수정
  • #11
    status 항상 FAILED
    원인: disposition 값이 STORE인데 "DELIVERED"와 비교
    → ResultCodeClassifier.isSuccess(resultCode) 로 변경
  • ✅
    Flink Job 3개 RUNNING 확인
    SendRequestJob · SendResultJob · RetryJob · TaskManager 슬롯 6개 사용 중
